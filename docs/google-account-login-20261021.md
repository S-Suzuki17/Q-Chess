# Googleログインと初回アカウント設定

対象はWebとCapacitor Android。通常のログインをGoogleに統一する。初回だけユーザー名、Q-Gambit専用パスワード、利用規約への明示的な同意を求める。Googleのパスワードを本アプリへ入力させない。ゲスト練習は継続できる。

## アカウントと本人確認

- Google AuthのIDとゲーム内のプロフィールIDを対応表で管理する。サーバーがGoogleの認証方法、実在セッション、対応表を確認し、クライアントが申告するゲームIDは信用しない。
- ユーザー名は英数字3〜15文字、大文字小文字を区別せず一意。専用パスワードは12文字以上・UTF-8で72バイト以内。通常のログインには使用しない。
- 専用パスワードはランダムなsalt付きscrypt（N=32768、r=8、p=3）でハッシュ化し、ブラウザーからアクセスできないスキーマに保存する。確認は時間一定比較、回数制限、同時ハッシュ処理数の制限を設ける。設定は[OWASPの推奨値](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)を参照した。
- アカウント削除・全端末のログアウトでは、専用パスワード確認後に操作とセッションへ結び付いた2分間有効・一度限りの確認票を発行する。Googleで改めて認証した直後は専用パスワードを再設定できる。
- 規約全文・プライバシーポリシーへのリンクと未選択の同意欄を表示する。初回設定と同じトランザクションで現在の規約版・サーバー時刻・アカウントに同意を保存する。今回、規約の版自体は変更しない。
- 旧アカウントの引き継ぎにはGoogle認証と以前のユーザー名・パスワードを両方確認する。メールアドレス一致だけでは結合しない。既存のレート・進行・券はプロフィールIDを維持して引き継ぐ。

## 保存ログイン

WebとAndroidでセッション保存・更新を有効にする。起動時の確認中はログイン画面を表示せず、サーバーで対応アカウントを確認してホームまたは保存された対局へ戻る。初回設定未完了なら設定画面を開く。トークン更新だけで対局画面を初期化しない。

キャンセル、ログアウト、別アカウントへの切り替え、コンポーネント破棄で古い非同期応答を無効にする。Googleコールバックに失敗した場合、古い保存セッションを新しいログインとして採用しない。通信障害時は保存情報を削除せず再試行を提供する。ログアウト・セッション失効・保存データの消去後は再認証が必要。

## 検証

- サーバー：Google認証方法・生存セッション・対応ID、旧ログイン閉鎖、同意必須、パスワードハッシュ、確認票の使い捨て・期限・操作制限、再設定時の新しい認証、リクエスト制限。
- フロント：保存復元、初回設定、通信復帰、トークン更新、キャンセルと応答の競合、Googleアカウント切り替え、Web/Androidのコールバック指定。
- 実PostgreSQL 17.11：8ケース成功。並行登録、一意制約、再送時の既存情報保持、旧パスワード誤りと成功、券・レート保持、同意失敗時の巻き戻し、ロール境界、退会時の連動削除。
- 配信用Web出力：合成アカウントでGoogleだけの入口、同意未選択からの初回設定、保存ログインの再読み込み、券0枚、再認証後の残高、通信復帰の6ケース成功。実Googleアカウントの作成や実取引は行わない。
- Androidの配信用出力、署名済みAAB、実端末でのGoogle往復は別々に記録する。ブラウザーの合成テストは実端末受入の代わりではない。

2026-10-21追加確認：既存機能を含む286ファイル・3,521テスト、型検査、サーバービルドが成功。WebとAndroidの公開設定付きビルドは各63個のJavaScriptを照合し、未解決の公開設定参照は0件。両ターゲットで各6件の画面テストが成功した。Androidアセットの同期は完了。SDK・Gradle保存先のFドライブはユーザーの接続により利用可能になり、署名ビルドを進行中。週替わり問題の広告だけを専用フラグで有効にし、対局間広告・動画報酬・購入UIのフラグは追加で有効化しない。

## 同期リリース

対象は既存のSupabase `gtxbvbsplfkkjlmnqath`、Render `Q-Chess`、Cloudflare Pages `q-gambit-web`、Android `com.qgambit.app`。ユーザーの実施承認と「My Workspace」の選択を引き継ぐ。

1. 審査・CIと配信用成果物を確認する。公開前に進行中の対局と設定を読み、必要な保守状態の変更は既存値へ条件付きで行う。
2. 未適用の学習報酬マイグレーションと `20261020153130_google_account_onboarding.sql` を適用する。既存プロフィール・券の一括更新や削除はない。変更した削除関数にある既存の履歴整理は関数の呼び出し時にのみ実行される。
3. Renderで `LEARNING_REWARDS_ENABLED=true` と `GOOGLE_ACCOUNT_LOGIN_ENABLED=true` を設定し、対象コミットのサーバーを反映する。別の環境変数を置換しない。
4. SupabaseでGoogle以外の通常ログイン提供を停止し、Web/AndroidのGoogleリダイレクトを確認する。Googleアプリの秘密情報は変更・出力しない。
5. 確認したWeb成果物をPagesへ公開する。Android成果物と配信状態は別記する。更新版の入手前に古いAndroidを最低ビルド番号だけで一律締め出さない。
6. 公開後にAPI・画面・マイグレーション・権限を確認し、保守状態を保存した元の値へ戻す。

障害時は直前のPages配信とRender配信へ戻し、追加フラグを元に戻す。追加テーブルは削除しない。旧パスワードログインのブラウザー権限を戻すことは認証方針の変更となるため、復旧に必要かを個別に判断する。公開結果・コミット・成果物のハッシュは実行後に追記する。
