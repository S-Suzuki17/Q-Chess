# CPU中断の調査と修正

本番WebでCPUサービスエラーによる中断と対局券返還の確認不能が報告された。直近の該当対局は2026-10-23 05:16 UTCに `cpu_unavailable` で無効化され、無料券1枚の返還行が同時刻に保存されていた。調査時点で未使用・有効期限なし、レート精算行は0件。追加の券付与やDB更新は行っていない。返還券は通常の無料券残高と別枠で管理される。

旧CPU探索では、動かせない最初の駒を調べている間に難易度別の思考予算を消費すると、合法手が残っていてもnullを返して対局を中断した。この経路を時計を制御したテストで再現した。ただし当時のログにはCPU失敗の内訳がなく、報告された一件の直接原因までは断定できない。

修正後は、最初の合法手を見つけるまでだけ有限の予備時間を使い、その後は通常の思考予算に戻る。ワーカーは合法手を評価処理の前に親へ渡し、3秒の実行上限に達した場合は最後に確保した手を返す。親は元の盤面バージョンを照合し、GameEngineでも再検証する。古い盤面に対するワーカー失敗では現在の対局を中断しない。合法手を確保できない障害は従来通り無効化・券返還し、レート勝敗にしない。失敗ログには固定分類・難易度・盤面バージョン・所要時間だけを残す。

検証は関連82テストとサーバービルドが合格。ビルドした本番ワーカーによる合成対局12手もすべて合法で、1msと210msの交互の思考予算に対して42〜266msで返った。外部対局・アカウント・台帳を作らない検証である。証拠は `build/supervision-20261023/cpu-recovery-tests.json` と `cpu-worker-acceptance.json`。別のオンライン統合テストはサーバー起動フックが10秒でタイムアウトし、CPUテスト実行前に停止したため、独立した実ワーカー検証で確認した。

反映対象は既存Render `Q-Chess` の対局サーバー。WebとAndroidが同じ修正を利用する。DBスキーマ・残高・クライアント配布物の変更はない。復旧先は修正前のRenderデプロイ `dep-dbde57m1egvs738irjr0`、コミット `5f7ae7a5f71a8bd382b6242c167450c12f398289`。
