## CPU-practice hint tickets: design and acceptance gate

Current `LocalGameBoard` computes a hint in a browser Worker; `useMoveHint` calls `onDelivered` immediately after scheduling React state, before the hint is actually painted. The existing `spendCpuHintAfterDelivery` adapter and `ticket_spend_receipts` table are dormant and store no position or hint. A client-submitted move or acknowledgement cannot prove a legal, delivered hint. Do not wire a debit to this callback.

1. Extract the Web quantum rules/search into a shared, versioned engine used by both client and server. Create an authenticated, server-owned `cpu_practice` session with owner, side, position/move log and revision. Server-replay each move and calculate/validate the hint for that exact revision. Reject missing, stale, finished, campaign, online, and ranked sessions; do not trust a client-supplied mode or board as proof.
2. Prepare a legal `{from,to}` hint on the server before any debit. Store the session/revision hash, move, owner, request ID and delivery state durably. In one DB transaction, check available free/eligible paid hint balance, debit at most once, and persist the immutable hint receipt. Repeating the same request ID returns that same hint without a second debit; using it for another owner or position fails. No legal hint or search timeout means no debit.
3. If the connection closes **before the debit transaction**, do not debit. If it closes **after commit but before the response is seen**, keep the already-paid hint retrievable on reconnect under the same authenticated session/request ID, at no extra charge. A server cannot prove that pixels rendered in a browser; do not promise literal post-delivery billing or silently discard a charged hint. Provide a support/recovery path for an unrecoverable delivery, with a guarded credit restoration if needed.
4. Keep a hard-coded release gate OFF until database migrations, shared-engine equivalence, reconnect replay and Android/Web behavior are verified. No CPU hint route may be mounted in a ranked match UI; also reject requests for users currently in an active ranked match on the server.

Acceptance tests: legal hint/arrow matches the shared engine; invalid/terminal/stale positions and search errors spend nothing; parallel requests and retries spend once; paid pool is never used while a free hint ticket exists; expired/refunded/off-price paid membership cannot spend its pool; disconnected-before-commit spends nothing and disconnected-after-commit replays the identical hint without another debit; a ranked session cannot obtain an official hint; account deletion invalidates sessions and receipts safely. Keep all spending flags OFF until these tests pass against a development database, not just mocks.
