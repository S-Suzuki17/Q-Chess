# 公開案内の確認記録

ここには実際に確認した記録だけを保存します。作業手順は `../public-content-maintenance.md` を参照してください。

`content-maintenance.mjs --draft` の出力は `status: pending` です。生成しただけでは確認完了になりません。

`changes[].gitBlob` はコミットされるソース内容のGitハッシュです。Gitの改行変換を適用して計算するので、Windowsで確認した記録もLinuxのCIで照合できます。下書き作成はステージングやGitオブジェクトの書き込みを行いません。

実際に対象ページとゲーム仕様を照合し、各項目に次を記入します。

- `decision`: `updated`（案内を修正）または `no-change-needed`（確認したが案内の変更は不要）。
- `reason`: どの仕様が変わり、案内にどう影響するか。変更不要ならその根拠。
- `checkedPages`: 実際に確認したページと見出し。
- `evidence`: 関連するソース、実行した検証と結果、比較した画面など。
- `reviewer`: 実際の確認者。Codexが確認した場合は `Codex` と明記。
- `status`: 上記の確認が終わってから `completed`。

対象ソースのハッシュや比較元が変わると記録は無効になります。案内を変更したと記録する場合は、対象の案内ファイルも差分に含まれている必要があります。変更後に再生成したテンプレートへ以前の結論を無確認で転記しないでください。
