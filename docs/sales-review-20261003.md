# T3/T5 販売規約・商取引開示レビュー

未公開。現行規約 `2026-09-25.1` は変更しない。新案 `2026-10-03.1` は発効日未設定のレビュー原稿。

## 実装する表示

- `/commerce/` は本人が公開承認した販売者の氏名・事業用住所・電話と問い合わせメールだけを表示する。生年月日、Stripe内部ID、決済資格情報を掲載しない。
- 月額総額 USD 2.99、月次自動更新、支払方法・請求時期、提供開始、通常解約は支払済み期間末まで、通常解約の日割り返金なし、法定権利は制限しないことを表示する。
- 会員券は無料券とは別枠。毎日対局券/CPU練習ヒント券各3枚、終了・返金・決済取消で未使用券失効、再加入へ持ち越さない。
- 会員券上限は2026年10月3日に本人が各60枚と承認。無料券各20枚とは別枠で、上限を超える分は付与しない。購入導線は新規約・最終リリース確認がそろうまで拒否する。
- 税登録が未確認のため、自動徴税を有効にせず、税を徴収しているとは記載しない。初回と更新請求の総額2.99を販売担当が実測する。
- Androidは特典利用・会員券残数のみ。価格、購入、請求管理、外部購入リンクを表示しない。

## 新規約を有効にする統合作業

`src/config/salesTermsDraft.ts` の本文をレビューし、各60枚の上限を含む本文と発効日を確定してから、クライアント `src/config/terms.ts`、サーバー `server/src/services/AccountTerms.ts`、全ての券/課金RPCの `account_terms_consents.version` を同一の要求版へそろえる。単にWebのversionだけを変更すると、APIは旧版同意を要求し続ける。

無料財布・ランク入場・CPUヒント・会員付与/消費/取消など、適用済みRPCを含めて新しいmigrationで差し替える。旧版同意だけのアカウントは再同意前に新規約対象claim/購入を行えないこと、最新同意アカウントは正常に利用できることをDBで確認する。既加入者の状態照会、Stripe Webhook照合、請求管理、退会前の購読解約は新規Checkout停止と独立して維持する。

未有効機能を実施済みとして発効しない。機能OFFの間は既存公開規約を使い、販売規約は下書きとする。新機能と新規約の公開を統合担当が同じリリース工程で扱う。

旧Play版はバンドル済みの旧規約版を同意APIへ送るため、サーバーの要求版だけを新案へ変えると `TERMS_UPDATED` になり、旧クライアントが新規約を確認・同意できなくなる。今回のコミットでは現行Web/サーバー/SQL版を変えず、この互換性を維持する。新案を発効する段階では、旧Play向けの規約表示・バージョン対応または更新導線を準備し、旧版同意だけで新たな購入ができないことと、問い合わせ・退会・既存購読の解約が止まらないことを別々に確認する。

本番財布migrationは公開担当が既に適用済み。production `20261003021514 / ticket_wallet_daily_login` は source `20260930083253_ticket_wallet_daily_login.sql` と名前＋checksumで照合し、source時刻が異なるという理由で再適用しない。本担当はこのmigrationを変更していない。
